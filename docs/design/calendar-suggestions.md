# Calendar suggestions — one button, or silence

**Date:** 2026-10-02
**Status:** Destination. The button exists. The calendar write does not.
**Spec:** TURTLE_SPEC §3.1 (the practitioner owns their practice). Companion: [mcp-connections.md](mcp-connections.md).

## What he sees

In his home channel, Turtle may post one potential date. One button puts it on his calendar. There is no decline button. Leaving it is the no.

The calendar is the one he connected. Accepting writes the date there, under his name. The post says which calendar, in one line.

Ignored dates and accepted dates are both remembered, as a class: a reminder to book something before a trip is not the same class as a note to write someone. A class he accepts may be offered again. A class he ignores is not offered again without a new reason. An offer he has not seen yet is not offered a second time.

## What is already true

`date_keep` posts **Datum merken** / **Keep this date**. Accepting writes the practice date file and is counted. The button gives up after three minutes. Silence in that window is not a decision about the date. Nothing in that path calls a calendar.

## What is not true yet

The calendar connection in [mcp-connections.md](mcp-connections.md) is not built. Until it is, accepting must keep writing the practice date file and must not claim a calendar was updated.

The offer belongs in the home channel, after something he said that names a date. It does not belong in every room, and it does not belong in a health channel. River does not start offering on its own.

## Abandon

Stop if a suggestion appears in a room that is not his, if accepting writes a calendar he did not connect, or if an ignored class is offered again with no new reason.
