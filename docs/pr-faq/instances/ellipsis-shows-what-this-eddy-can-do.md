# `...` prompts everyone who lives here

**Audience:** the practitioner in an eddy.
**Status:** purpose held. River buttons and Memory glance live 2026-09-05. One store; each inhabitant practices with it their own way.

## Headline

Type `...` for the glance: Turtle says what it understands about this conversation and names one plan. River answers with buttons. Memory shows the related sediment. Type `.` when that assessment and plan landed — then Turtle goes on. Same pair as Magic.

## Problem

The standing bar always looks the same. It cannot know that this thread has become a meal plan, or that a research eddy has just opened a question about reaching out.

A first craft play also showed a second problem: Turtle listed River's acts as if they were its own. The glance worked. The ownership was wrong.

A third problem is already live on every turn: the memory agent already speaks, unasked, as a step card ("remembering: …"). That card is often the hottest topics in the house, not the memories this conversation reaches for. Family has landed on craft that way.

## Solution

`...` is an agreed glance — assessment plus a plan. It prompts **all three** inhabitants.

**Turtle** names where the conversation is, then **one** next move it would run. Not a menu of capacities. Other words steer. `.` after that glance is resonance approval — proceed.

**River** shows the platform acts that are valid for this work, as buttons. Checkpoint. Share. Pin as artifact when the thread has become a thing.

**Memory** shows the sediment this conversation actually reaches for — related topics and short excerpts, not the hottest three in the house. Quiet when nothing related exists. The same room boundaries as always: craft does not show family; a shared room does not show another person's private root.

Neither partner guesses which act will be picked. Memory does not narrate "I remember." It shows. Naming the situation is orientation, not Clippy.

They share one store (`memory/`). Each practices with it differently. Turtle is not blind: every turn it carries the packet — heat, plus what the current message reaches for. Memory's glance is a different cut: related to this conversation. Turtle does not read River's card before it answers. Feeding the glance back into Turtle would put Discord on the wire and collapse three practices into one. (Held 2026-09-05.)

`.` is "yes — that is it. Go." It never opens a glance.

## Benefits

- One glance, every inhabitant, each in its own voice.
- Memory becomes something you asked to see, not a card that talks over you.
- The list follows the work. Platform acts stay tappable. Thinking stays talk.
- `.` and `...` stay distinct.

## FAQ

### UX

One glance, three surfaces. Turtle never lists `!checkpoint`. River never writes a paragraph of options. Memory never dumps the house's hottest topics. The practitioner never gets an unsolicited guess. `.` never opens any of the three. Turtle's words and Memory's card may differ — that is two practices, not a sync failure. As long as Turtle is not blind, that difference is allowed.

### Not in scope

Hiding the standing bar. Changing parent-river `.`. Making eddy `...` mean go-on. Widening craft memory to include family. The `#turtleOS` mirror channel. A third Discord bot named Memory. Feeding River's glance into Turtle's prompt so the two mouths match.

### Approach

Craft play first. Turtle-half is a practice-root instruction (already live). River posts the shared act list as buttons. Memory scores the thread's name, note, and recent talk — not the `...` itself — and posts related sediment only. The unasked “remembering:” line on the step card comes off in the same change. Bar stays. Parent-river `...` is not a breath.

### Risks

Turtle keeps listing River acts or reciting memories — the first Derek glance did the former; the step card was the latter. If Memory shows heat instead of relevance, the glance is the same leak with a new trigger. A list of moves with no recommended next is not a glance. The old "do not rank" line is retired: the plan *is* the glance.

### Success / UX verification

In the Derek eddy, `...` names the open question and one plan (not a menu); River shows checkpoint; Memory shows earlier Magic / Positive-AI / Source Library sediment — not marriage conflict. In a meal-plan eddy, River shows pin-as-artifact; Memory shows prior meal-plan notes if they exist. Empty eddy: all three stay thin. The step card no longer lists topics.
